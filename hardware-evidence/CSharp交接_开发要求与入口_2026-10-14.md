## 1. 核心主旨：C# 与 Java 分离

这是整个工程的最高原则。C# 与 Java 的交界**只有四个接触口**：

| 口 | C# 侧 | Java 侧 |
|---|---|---|
| ① 参数 | ArgumentList 逐项 8 项 | 启动器消费前 3 项（-cp/类路径/类名），main 收后 5 项 |
| ② 日志 | 双管道按 UTF-8 读取 | setOut/setErr 显式 UTF-8 输出 |
| ③ 退出码 | 读 Process.ExitCode | System.exit(run 返回的 int) |
| ④ 任务目录 | C# 先建空目录 | Java 只校验 --out，绝不创建 |

**除这四口外两侧完全分离**：源码互不读取、各自独立构建、互不依赖内部实现。不要读 Java 源码来写 C#，也不要让 C# 依赖 Java 的内部结构（record 名、方法排列等契约未冻结的东西）。

## 4. 权威契约：demo-args-v1

**权威文件**：`csharp/CONTRACT.md`（就在你工作目录里）。以下摘要，冲突以 CONTRACT.md 为准。

### C# 输入

```
Caller <javaExecutable> <classDirectory> <runsRoot>
```

三项均非空 Windows 完整绝对路径；不依赖当前工作目录。

### C# 侧必须遵守的行为

1. 启动前：校验配置 → 生成 executionId（Guid N 格式，32 位小写十六进制）→ 建任务路径 `runsRoot/run-<id>` → 确保路径原先不存在（占用即拒绝，不复用不清空）→ **创建空目录后才启动 Java**
2. ArgumentList 按序逐项 8 项，**禁止 shell 拼接带引号的整条命令**：`-cp`、`<classDir>`、`DemoCommand`、`demo`、`--execution-id`、`<id>`、`--out`、`<taskDir>`；路径项不额外包引号（中文/空格路径已实测无损）
3. `UseShellExecute=false`、`CreateNoWindow=true`、双管道重定向、**双路显式 UTF-8**
4. **等待进程结束之前**启动双管道异步读取（防管道堵死）；读取任务注册故障观察（防未观察异常）
5. 退出码分类（**只认退出码，不解析日志标记**）：
   - 0 → `validated`（只表示参数校验通过，成功文案只能是"本次参数校验通过"，不得扩义为硬件正常/报告生成）
   - 2 → `request_invalid`
   - 其他 → `java_failure`（保留原退出码）
   - 配置/创建/启动/日志失败 → `caller_failure`
   - 超时 → `timeout`（**javaExitCode 必须为 null**，不得借用停止后退出码）
6. 期限：10 秒自然等待 → 超时只 Kill **本次持有的 Process**（entireProcessTree:true，不按进程名扫杀）→ 最多 3 秒确认退出 → 日志收尾共同 3 秒上限；无自动重试、**不删除任务目录**（成功失败都保留供核查）
7. Caller 自身退出码：validated=0、request_invalid=2、其余=1；`javaExitCode` 字段保留 Java 原值，两者不得混淆
8. 结果输出为内存对象转 JSON 打印到控制台（camelCase，枚举 snake_case）；**不写 result.json/result.tmp**（那是后续切片，未在契约内）

### 结果对象字段

executionId / taskDirectory / status / javaExitCode / stdout / stderr / error（创建前失败时前两者可为 null）。

- **F1 编码差异**：JVM 在 main 执行前报错（类加载失败等）走 JVM 内部通道，用系统编码（中文 Windows=GBK）输出；C# 按 UTF-8 读该部分会乱码。**不影响分类**（分类靠退出码）。修复需要给启动参数加 `-Dsun.stderr.encoding=UTF-8`——属契约参数结构调整，**当前契约下不得擅自加**，留待新契约版本

### 证据分级纪律（必须坚持）

每个结论标注：**已实跑 / 静态审阅 / 未验证**。构建成功≠运行正常；替身测试≠真实联调；助手运行≠本人实践。不得用静态审阅替代编译通过。
